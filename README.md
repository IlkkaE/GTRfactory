# GTRfactory

## Nykytila — 14.9.2026

Basson rakentamista tuetaan nelikielisellä bassolavalla; viisikielinen vaihtoehto on poistettu. Kolme kitaralapaa säilyvät. Nykyinen projektiformaatti on **v11** ja laparakenne **v3**. Uusi projekti on oikeakätinen, ja **Right-handed / Left-handed** -toggle vaihtaa koko instrumentin esityksen sekä viennit. V10 ilman handedness-arvoa tai `right`-arvolla luetaan muistiin v11:nä; v10:n `left` tai muu kätisyysarvo hylätään. V9 ja vanhemmat tiedostot hylätään ilman muunnosta. Paikalliset basso- ja kätisyyspäivitykset eivät sisälly alla kuvattuun 12.9. julkaisuun.

## Current localization status

The application UI is currently English-only. This includes the File menu, editor panels, dialogs, status and error messages, import/export controls, accessibility labels, headstock and pickup names, and human-readable PDF/export labels. The document language is `en`.

The current visible editor group labels are **Basic dimensions**, **Fit**, **Advanced settings**, and **Import**. A new project starts unnamed, with **Name your project** as the name-field placeholder. Existing project names and other user-provided text are preserved when a `.gtrfactory` file is opened or saved.

The English UI conversion on 12 September added no language switch or i18n layer and preserved the then-current v9 schema, machine identifiers, export roles, layer names, source filenames and millimetre geometry. The current local editor uses the v11 document format; the shared snapshot includes the earlier English UI conversion, not this local bass update; deployment status is recorded in the workshop release ledger.

## Current editor tools

The current editor also provides the following local workflows:

- **Show original body** is a built-in, non-interactive outline of the original starter body. It is thin, purple, dashed and on by default. It appears in all three body views and their thumbnails, but is hidden during neck/headstock editing. Visibility is session-only and does not change the project, bounds, exports or undo history. **Reference overlay** remains a separate user-loaded `.gtrfactory`, PNG or JPEG reference.
- Clicking or keyboard-selecting the headstock opens its editing view. An unchanged neck draft closes without a document or history change. A pending valid neck draft opens **Apply neck changes and edit headstock?**: **Apply and continue** commits the neck change once and opens headstock editing; **Cancel** or Esc retains the draft. Invalid drafts remain available for correction.
- **Reset body** restores only the body outline, preserving the name, neck/headstock, pickups and rear cavity, and re-derives the current neck mouth or manual pocket. It supports Undo/Redo and creates no history when nothing changes. An incompatible neck-joint reference or a pickup that would no longer fit prevents the reset without altering the project. The button is disabled during a drag, neck draft or headstock editing.
- **Right-handed / Left-handed** is the single handedness toggle in the toolbar. New projects default to right-handed; left-handed display mirrors the complete instrument, including the body, neck/headstock, pickups and rear cavity, while canonical millimetre coordinates, text, rulers and bass/treble semantics remain unchanged. The switch is one Undo/Redo step and is blocked during an active drag or open neck draft until it is applied or cancelled.
- **Grid** cycles **Off → 10 mm → 5 mm → 1 mm → Off**. Snapping applies only to pointer-dragged body nodes and handles; group movement uses one shared snap delta. Numeric fields, keyboard movement, Add point, headstock, pickups and electronics cavities are not grid-snapped. At zoomed-out levels fewer grid lines are drawn, while snapping remains exact. Grid settings are session-only and do not affect saved files or exports.
- The rear electronics cavity now follows the body's **Back** orientation. Both recess and inner profiles use the corrected shared geometry in the editor and exports. Existing v11 cavity dimensions, centre and profile version stay unchanged; v10 right-handed documents are read into v11 and their displayed/exported orientation is intentionally corrected.
- The current `potero-v1` / version 1 profile is directly replaced from the approved source SVG for new and existing v11 documents; right-handed v10 documents are read into v11 without a separate migration step. The stored centre and horizontal/vertical dimensions remain unchanged. The current starter outer bounds are 176.06686788504933 × 81.36283544639431 mm; the source page is 237 × 123 mm and is not the geometry bounds. Both source contours remain closed and the Back transform is unchanged.

GTRfactory on paikallinen, selainpohjainen työkalu oman sähkökitaran rungon ja kaulan suunnitteluun. Toteutettu runkoeditori aloittaa käyttäjän toimittamasta `CDR/bodytemplate.svgz`-lähteestä muunnetusta 21 solmun suljetusta Bézier-rungosta (lähtömitta noin 309,6 × 451,3 mm). Sovellus käyttää Reactia, TypeScriptiä, Viteä ja Zustandia.

## Käyttö

Edellytys on Node 24.15.0 ja npm 12.0.1. Aja komennot projektin juuressa peräkkäin. Käytä projektin omaa lukitustiedostoa:

```powershell
npm ci
npm run dev
```

Kehitysnäkymä on osoitteessa `http://127.0.0.1:5174`. Portti on kiinteä: varattu portti on tarkoituksella virhe, jotta palvelin ei siirry huomaamatta toiseen osoitteeseen. `test:port-conflict` tarvitsee portit 5174 ja 4174 vapaiksi; `test:e2e` tarvitsee preview-portin 4174 vapaaksi.

```powershell
npm run typecheck
npm run test:run
npm run test:port-conflict
npm run build
npm run test:e2e
```

Koodin ja testien sovittu aktiivinen muotoilu tehdään Prettierillä komennoilla `npm run format` ja `npm run format:check`. Ne kattavat `src/**/*.{ts,tsx,css}`-tiedostot vendor-alueen ulkopuolelta, `tests/**/*.ts`-tiedostot sekä Vite-, Vitest- ja Playwright-konfiguraatiot ja porttitarkistusskriptin. JSON-, vendor-, referenssi-, tutkimus- ja dokumenttitiedostoja ei muotoilla näillä komennoilla.

Tuotantobuildin voi tarkistaa erikseen komennolla `npm run preview` osoitteessa `http://127.0.0.1:4174`. `test:port-conflict` tarkistaa, että varattu dev- tai preview-portti aiheuttaa virheen eikä palvelin vaihda porttia. `test:e2e` tekee aina uuden tuotantobuildin ja tarkistaa sen asennetulla Microsoft Edgellä; leveän työpöytäkokeen lisäksi kapea koe on iPhone 13 -kokoinen Chromium-simulaatio. Jos Microsoft Edgeä ei ole asennettu, testiä ei voi pitää tehtynä. Testit käyttävät projektin omaa Playwright-riippuvuutta eivätkä tarvitse Codexin mukana toimitettuja kirjastoja.

## Editorin käyttö

Suuri näkymä on vasemmalla ja kaksi pienempää, samaan malliin sidottua esikatselua oikealla. **Front**-, **Back**- ja **Neck pocket** -näkymän voi nostaa suureksi napsauttamalla pikkukuvan mitä tahansa kohtaa, valitsemalla pikkukuvan näppäimistöllä ja painamalla Enter/välilyönti tai käyttämällä 1/2/3-oikoteitä. Näkymien otsikot ovat tekstejä; erillisiä Runko-, Kaula- tai näkymänvaihtopainikkeita ei ole. Etu- ja takanäkymissä näkyvät rungon ulkoreuna sekä katkoviivainen keskiviiva; taskunäkymässä näkyy rungon yläosa ja automaattisesti johdettu suljettu taskukontuuri, jossa on avoin kaulalovi. Kaikissa näkymissä on leveys- ja pituussuunnan asteikot. Suuressa etu- ja takanäkymässä on lisäksi rungon ulkoreunaan kohdistetut mittaviivat; niitä ei näytetä pikkunäkymissä eikä kaulataskunäkymässä. Mittaviivojen lukemat perustuvat rungon todellisiin Bézier-käyrän ääriarvoihin, eivät piirtoalueen reunaan.

Sapluunageometria muodostetaan sisäisenä millimetripohjaisena geometriatuloksena. Etu on rungon suljettu ulkoreuna ja taka sen tarkka peilaus; tasku on automaattisesti johdettu rungon yläosan suljettu kontuuri, jossa on avoin kaulalovi, taskun sivut, pyöristetty pää ja taskun päädyn + 20 mm:n kohdalle sijoittuva suora alareuna. Rungon Bézier-kaaret säilyvät täsmällisinä käyräosuuksina ja taskun pyöristykset ympyräkaarina, ja alkuperäiset kaulaliittymän suukäyrät sekä keskiviiva ovat erillisiä viitteitä. Taskunäkymän virheellinen tai tukematon topologia näytetään diagnostiikkana ja säilyttää editorin muokattavana.

Rungon ja kaulan esikatselu on vaakasuuntainen: oikeakätisen kaula osoittaa oikealle ja vasenkätisen vasemmalle kaikissa Front-, Back- ja Neck pocket -näkymissä. Kätisyystoggle käyttää editorissa samaa effectiveMirror-muunnosta (Back XOR Left-handed) sekä vasenkätisen esityksen suuntakiertoa ja käänteisiä osoitin-/mittaustapahtumia; body, lapa, pickupit, potero ja poteron kahvat seuraavat näytön suuntaa yhteisen näyttö→maailma-delta-muunnoksen kautta. Vaaka-asteikko näyttää Y-koordinaatit rungon pituussuunnassa ja pystyasteikko X-koordinaatit leveyssuunnassa; rungon leveysmitta on vasemmalla ja pituusmitta alhaalla. Nuolinäppäimet liikuttavat valittuja solmuja näkyvän suunnan mukaan (1 mm, Shift 10 mm). Desktopin pikkunäkymäsarake on 180–240 pikseliä, ja kapealla näytöllä pikkunäkymät siirtyvät suuren näkymän alapuolelle vierekkäin.

**Reference overlay** -osasta voi avata yhteen istuntoon yhden v11-muotoisen tai oikeakätisen v10-muotoisen `.gtrfactory`-projektin tai PNG- tai JPEG-referenssin. Projektireferenssin kanoninen muoto esitetään aktiivisen projektin kätisyyden mukaan. Haamu voidaan näyttää tai piilottaa, himmentää, keskittää, poistaa ja sijoittaa X/Y-siirrolla sekä korkeudella kuvasuhteen säilyttäen. Haamu ei ole muokattava eikä vaikuta rungon mittoihin, tallennukseen, undo-historiaan tai valmisprojektiin; **New**-toiminto, onnistunut **Open**-toiminto ja sivun lataaminen tyhjentävät sen.

Aloitusmuodon kaulaliittymän suojattu ketju seuraa kolmea ankkuria. Ketjun kahvat ovat lukittuja vain sen kahden suojatun segmentin osalta; `starter-21.in` ja `starter-02.out` jäävät vapaiksi, jotta niiden ulkopuoliset liittymät eivät lukkiudu vahingossa.

**Edit**-työkalulla solmuja ja kahvoja voi siirtää, valita Shiftillä tai laatikolla sekä siirtää nuolilla (1 mm, Shift 10 mm). Valinnan työkalut näkyvät kiinteässä rivissä työtilan yläpuolella: yhdelle solmulle X/Y, Smooth/Corner ja Delete point; usealle solmulle valittujen määrä ja sallittu poisto; reunaviivalle **Add point** ja Straight/Curve. Ilman valintaa rivi näyttää lyhyen ohjeen. Lukittu kaulaliittymä näyttää suojauksen syyn ja **Neck fit** -reitin, kun kaula on käytössä. Solmun, monivalinnan ja reunaviivan vaihtaminen ei muuta piirtoalueen kokoa. X/Y-kentät hyväksyvät millimetri- tai tuumasyötteen Enterillä tai poistuttaessa kentästä; Esc peruu syötteen. Ctrl/Cmd+Z kumoaa; Ctrl/Cmd+Shift+Z tai Ctrl+Y palauttaa muokkauksia. Välilyönti+veto, keskipainikkeen veto tai Pan view -komento panoroi, rulla ja +/− zoomaavat ja **Fit to view** palauttaa sovituksen. Suuren näkymän kamera ja pienet sovitusnäkymät toimivat erillään. Päällekkäisissä osumakohdissa solmu on kahvan edellä; lähennä kuvaa erottaaksesi lähekkäiset kahvat tai reunaviivan. Solmun ja reunaviivan voi valita myös Tab-kohdistuksella ja Enterillä/välilyönnillä.

Reunaviivan valinta näyttää ennakkomerkin lähimmässä käyrän kohdassa. **Add point** jakaa reunaviivan siinä kohdassa rungon muodon säilyttäen; uusi piste valitaan ja lisäys kumoutuu yhdellä Undo-toiminnolla. Suoralla käytetään lineaarista kohtaa ja Bézierillä käyrän omaa parametria. Päätepisteeseen tai nollapituiseen kohtaan ei lisätä päällekkäistä nodea. Näppäimistöllä valitun reunaviivan oletuskohta on parametrin puoliväli, ja merkki näyttää sen.

Uusi projekti sisältää heti kuusikielisen, 22-nauhaisen oletuskaulan, jonka mensuuri on 25,5 tuumaa eli 647,7 mm. Lapa näkyy kaulan jatkeena. Kenttään **Fret at center node** syötetään kokonaisluku 1–kaulan nauhamäärä. Valitun nauhan käyrä kulkee kiinteän keskinoden kautta; uuden kaulan oletus on 17. nauha ja offset 0 mm. Nauhan vaihtaminen nollaa aiemman pituussiirron samassa luonnoksessa. Nykyiseen v11-projektiin tallennettu offset säilyy avattaessa; **Align fret to center node** nollaa sen erillisellä valinnalla. Molemmat päätyvarat mitataan viimeisen nauhan rungonpuoleisimmasta pisteestä keskiviivan suuntaisesti. **Neck end allowance** on 10 mm ja **Fretboard end allowance** 16,35 mm; niiden 6,35 mm:n erotus näytetään otelaudan ylityksenä. Otelaudan päätyvaran on oltava aidosti suurempi kuin kaulan päätyvaran, ja koko viimeisen nauhan käyrän on mahduttava fyysisen pyöristetyn kantapään sisään. Corner radius on 6 mm ja kokonaisväljyys 0 mm. Lähtötila on puhdas ja muutoshistoria tyhjä. Kaulatasku johdetaan vain kantapäästä. Pelkkä otelaudan päätyvaran muutos säilyttää kantapään, taskun, rungon liittymän sekä satulan ja tallan paikat. Pelkkä kaulan päätyvaran muutos siirtää kantapään ja taskun päätyä mutta säilyttää otelaudan päädyn. Nämä aloitusarvot ja ylityksen rajaus ovat sovelluksen suunnittelupäätöksiä, eivät yleinen kitarastandardi. FretFactory-tuonti säilyttää sijoituksen sekä molemmat päätyarvot.

Kaula valitaan suoraan suuren etukuvan kaulasta hiirellä, kosketuksella tai näppäimistöllä. Työtilan yläpuolelle avautuu kontekstisidonnainen kaulapaneeli, jossa on **Basic dimensions**, **Fit**, **Advanced settings** ja **Import** -ryhmät. **Fit**-ryhmässä ovat erilliset Neck end allowance- ja Fretboard end allowance-kentät sekä yhteinen Corner radius. Kaikkia kenttiä ei pidetä yhtä aikaa esillä. Kaulapaneelin aikana erillinen rungon kontekstirivi piilotetaan. Etukuvassa näytetään muokkaamisen aikana nauha- ja kieliapuviivat. Normaalisti Etu näyttää valittavan otelaudan yhtenäisen ääriviivan, ohuen katkoviivaisen fyysisen kantapään, satulalinjan ja kaulageometrian todellisen tallan kontaktiviivan; rungon reuna näkyy kaulan läpi. Taka näyttää rungon reunan, keskiviivan ja elektroniikkapoteron kaksi reunaa; taskunäkymässä on kantapäästä johdettu avoin U ja rungon yläosa.

Kelvollinen kenttäluonnos päivittää kaikki kolme näkymää heti. **Accept** tai kentän Enter tallentaa kokonaisuuden yhtenä kumottavana muutoksena ja sulkee paneelin. **Cancel changes** tai Esc palauttaa hyväksytyn geometrian ja sulkee paneelin. Muuttumaton paneeli sulkeutuu myös bodyn, tyhjän piirtoalueen tai toisen näkymän valinnasta. Keskeneräinen muutos säilyy kenttäryhmä-, yksikkö- ja näkymävaihdossa; silloin bodymuokkaus odottaa hyväksyntää tai peruutusta. Virheellinen syöte säilyttää viimeisen kelvollisen esikatselun ja estää hyväksymisen. Kentän muokkaus tai hyväksyntä ei nollaa kameraa. Sulkeutuvan paneelin tila palautuu desktopissa kitarakuville.

Suuren Kaulatasku-kuvan kumman tahansa suljetun päätykulman napsautus avaa **Fit**-ryhmän ja kohdistaa **Corner radius**-kenttään. Yhteinen säde pyöristää sekä fyysisen kantapään, otelaudan että taskun päädyn; erillistä otelaudan säätöä ei ole. Molemmat kulmat korostuvat saman asetuksen vaikutusalueena. Myös terävä kulma (säde 0) on valittavissa. Kulman voi valita näppäimistöllä Enterillä/välilyönnillä; taskulla ei ole itsenäisiä vedettäviä kulmia. Keskeneräiset ja virheelliset kaulakentät säilyvät kulmavalinnassa. Jos nykyisen v11-projektin tasku ei liity automaattiseen kaulaan, kulmavalinta selittää rajan eikä luo kaulaa.

**Import**-ryhmässä liitetään FretFactoryn koko suunnitelma-URL tai pelkkä `#state=...`-osa ja valitaan **Import FretFactory design**. Tuonti toimii ilman verkkoa, vaatii kaikki laskennan tarvitsemat parametrit ja päivittää kaulaluonnoksen. **Accept** ottaa tuonnin käyttöön. Kokonaisväljyys jaetaan taskun sivuille puoliksi; negatiivinen arvo tekee taskusta kaulaa kapeamman. Collision- ja containment-tarkistukset ovat suunnittelutarkistuksia, eivät valmistuskelpoisuuden todistus.

Kaulaton nykyinen v11-projekti säilyy avatessa muuttumattomana. Tunnistettu kaulaliittymä voi näyttää katkoviivaisen 25,5 tuuman / 22 nauhan kaulatemplaten; valinta käynnistää tilapäisen luonnoksen, joka korvaa tallennetun tilanteen vasta **Accept**-toiminnolla. Hyväksyntä korvaa mahdollisen tallennetun manuaalisen taskuluonnoksen automaattisella taskulla; yksi Undo palauttaa alkuperäisen v11-dokumentin. Ilman tunnistettua liittymää runko avautuu ja tallentuu, mutta kaulan sijoitukselle kerrotaan este. Vanhat v1–v9-tiedostot hylätään ennen nykyisen työn korvaamista; niitä ei muunnetta nykyiseen formaattiin.

Etu-näkymässä näkyvät yhdeksän nimettyä 2D-mikrofonikolojen suunnitteluprofiilia. Uusi projekti aloittaa yhdellä SH-12-humbucker-profiililla 50 mm:n päässä tallan kontaktiviivasta, kolon keskeltä mitattuna keskiviivalla, ja **+ Pickup cavity** lisää valitun profiilin kelvolliseen kohtaan rungon keskiviivalla. Valikossa ovat SH-12 Humbucker, SSL-1 Strat single-coil, STR-1 Tele neck, STL-1b Tele bridge (17°), SP90 SGZ P-90 soapbar, SD HB7, SD HB8, EMG707 ja EMG808. Lisäys valitsee kolon ja vaihtaa Etu-näkymään; kolon klikkaus avaa sen kontekstityökalut. Koloa voi vetää keskiviivalla, vaihtaa mallia, syöttää etäisyyden tallaan mm- tai tuumayksikkönä ja poistaa. Jokainen hyväksytty toiminto on yksi undo-askel; Esc peruu vedon tai kenttäluonnoksen. Kaulan muuttaminen pitää kolon rungon koordinaatistossa ja päivittää tallan etäisyyden; ristiriita estää kaulamuutoksen hyväksynnän. Kolon kaulanpuoleinen sijoitusraja huomioi otelaudan päädyn, joten koloa ei sijoiteta otelaudan ylityksen alle.

Lapa näkyy oletuksena Etu-kuvassa kaulan jatkeena. Lavan napsautus, kosketus tai Enter/Space lähentää saman piirtoalueen lapaan ja avaa sallitut solmu- ja kahvatyökalut. **Headstock template** -valikossa kuusikieliselle ovat Inline, 3+3 — Headstock 2 ja 3+3 — Headstock 3; 7- ja 8-kieliselle vain Inline. Satulaliittymän ja viritinreunan suojatut solmut sekä kahvat ovat lukittuja. Inline-reunan neljä päätyasemaa ovat suojattuja ja vapaa kaari ulottuu pisteestä 2 viimeiseen pisteeseen; 3+3-lähtömallien solmut 0/1/2/6/7/8 ovat suojattuja ja lähtömallin solmut 3/4/5 vapaita ja liittymäkahvat 2.out/6.in vapaita. Vapaalle kaarelle voi lisätä pisteen tarkalla De Casteljau -jaolla tai poistaa valitun vapaan pisteen Delete point -painikkeella tai Delete-näppäimellä. Valinnan Delete ei poista solmua tekstikentästä kirjoitettaessa, ja vähintään yksi vapaa piste sekä 128 solmun yläraja säilytetään. **Fit to view** palauttaa koko kitaranäkymän. Lapa käyttää v11-projektiformaattia. Kitaralavat tukevat 6-, 7- ja 8-kielisiä kauloja; neljälle kielelle valitaan bassotemplate. Muut tukemattomat kaulat säilyvät ilman muokattavaa lapaa. + Pickup cavity on piilossa lapaeditissä ja palautuu runkomuokkaukseen palattaessa. Mallinvaihto, kaulaluonnoksen 6→7/8 Inline -vaihto, solmun lisäys ja poisto ovat atomisia undo-askeleita; kitaralapojen mallikohtaiset muokkaukset säilyvät kitaramallien välisissä vaihdoissa, tallennuksessa ja avauksessa. Bassomalliin tai siitä pois vaihtaminen palauttaa valitun templaten asetukset vahvistuksen jälkeen. Kitaralavan nimellisen M6 Mini -sovituksen tila ja suurin satulakulma näytetään vain suunnittelun 2D-tarkistuksena. Avattu kaulamuokkaus on hyväksyttävä tai peruttava ennen lavan muokkausta.

Projektitoiminnot löytyvät **File**-valikosta. Tallennus ja lataus pyytävät hyväksymään tai perumaan keskeneräisen kaulamuutoksen ensin. **New** ja **Open** käsittelevät luonnoksen tallentamattomana työnä: peruutus, epäonnistunut avaus ja lukemisen aikana syntynyt uusi muutos säilyttävät työn. Myös kaulaluonnoksen muutos estää myöhässä valmistuvaa tiedostoavausta korvaamasta uudempaa työtä.

**Save** on ainoa projektin tallennustoiminto. Jos **Project name** on tyhjä, **Name your project** -dialogi pyytää 1–160 merkin nimen; Cancel tai Esc peruu nimeämisen muuttamatta dokumenttia. Tuetussa selaimessa ensimmäinen Save avaa tiedostovalitsimen ja ehdottaa projektin nimestä muodostettua `.gtrfactory`-tiedostonimeä. Onnistuneen tallennuksen jälkeen seuraavat Savet kirjoittavat samaan tiedostoon ilman uutta valitsinta. Projektin nimen muuttaminen pyytää uuden tallennuskohteen; vanhaa tiedostoa ei nimetä uudelleen tai poisteta. Tiedostovalitsimessa valittu nimi ei muuta projektin sisäistä nimeä.

Selaimessa, josta tallennusrajapinta puuttuu, sama **Save** aloittaa uuden kopion latauksen ja kertoo selvästi, ettei selain voi ylikirjoittaa edellistä tiedostoa. Selain voi lisätä ladatun tiedoston nimeen järjestysnumeron. Latauksen käynnistyminen ei todista tiedoston lopullista tallentumista levylle. Natiivin valitsimen peruutus tai kirjoitusvirhe ei käynnistä latausta automaattisesti; virheestä kerrotaan ja muokattu työ säilyy.

**Open** käyttää tuettua selaimen tiedostovalitsinta ja sitoo onnistuneesti avatun tiedoston saman istunnon Save-kohteeksi. Muissa selaimissa avaus käyttää tavallista tiedostosyötettä eikä saa ylikirjoitettavaa tiedostokahvaa. Tiedosto validoidaan ennen työn korvaamista; peruutus, virheellinen tai vanhentunut avaus säilyttää nykyisen työn ja aiemman tallennuskohteen. **New** ja onnistunut uuden projektin avaus vaihtavat tallennuskohteen. Kahva on vain istuntokohtainen: sivun uudelleenlatauksen jälkeen tiedosto on avattava tai tallennuskohde valittava uudelleen. Samanaikaiset tallennukset estetään, ja tallennuksen aikana tehdyt myöhemmät muokkaukset jäävät **Modified**-tilaan. Keskeneräinen tai virheellinen kaulaluonnos sekä aktiivinen veto estävät tallennuksen. Muuttumaton kaulapaneeli voi jäädä auki nimettyä projektia tallennettaessa; nimettömän projektin puhdas luonnos suljetaan ennen nimeämistä.

Projektit ovat `.gtrfactory`-päätteisiä JSON-tiedostoja. Tallennus käyttää formaatin versiota 11, jossa pakollinen `handedness` on `right` tai `left` sekä kaulan parametrit, laskentaversio, sijoitus, `endMarginMm`, `fretboardEndMarginMm`, tulosgeometrian snapshot, muuttumaton liittymäreferenssi, versionoitu headstock v3 -rakenne (aktiivinen mallin tunniste ja kaikkien neljän mallin kanoniset variantit) sekä kaulan `physicalProfile` (basson fyysiset satula- ja 12. nauhan leveydet, kitaralla `null`), mikrofonikolojen profiiliversiot sekä `centerYmm`-sijainnit tallennetaan. V11 vaatii validin `handedness`-arvon; puuttuva tai muu arvo hylätään atomisesti. Oikeakätinen v10 luetaan `right`-arvolla v11-dokumentiksi, mutta v10:n vasenkätinen tai muu kätisyysarvo hylätään. V1–v9 hylätään ennen nykyisen työn korvaamista. Vain v10:n vanhan passiivisen `bass-5-inline`-avaimen puhdistus sallitaan lukupolussa; v11:ssä sama avain hylätään. Aktiivinen viisikielinen bassolapa hylätään viestillä “Five-string bass headstocks are no longer supported.” ennen nykyisen työn korvaamista. Muita vieraita varianttiavaimia ei hyväksytä. Automaattista 5→4-muunnosta ei tehdä. Profiilin tuntematon versio hylätään ennen nykyisen työn korvaamista. Kaulan tallennettu laskentatulos tarkistetaan uudelleen; eri JavaScript-ympäristöjen erittäin pieni laskentapyöristys sallitaan, mutta muuttunut geometria tai rakenne hylätään. Kolojen tekninen enimmäismäärä on 64. Uuden kaulan luonnissa `body.neckPocket` on `null`. Tyhjä mikrofonikololista säilyy tallennuksessa ja avauksessa tyhjänä.

Editorin tekniset rajat ovat 2 MiB UTF-8-tiedosto, enintään 2000 solmua ja koordinaattien sekä kahvojen itseisarvo 1 000 000 mm. Nämä ovat parserin ja numeerisen käsittelyn rajoja, eivät yleisiä kitaran kokorajoja. Rungon itseleikkausvaroitus käyttää kuutiokäyrien 16 näytettä ja enintään 250 000 pari-vertailua; se on approksimaatio luonnosta varten eikä valmistustodiste.

**Export / print** avaa yhteisen ikkunan PDF-, SVG- ja DXF-viennille. Valitse etu- tai takarunko, kaula, otelauta, lapa tai kaulataskusapluuna; valitsemattomat osat ja tyhjät CDR-tyyliset paikat poistuvat asettelusta. Kaula sisältää lavan yhtenäisenä kontuurina, ja lapa voidaan valita myös erillisenä detaljina. Leikattavat ääriviivat, mikrofonikolot, elektroniikkapoteron molemmat reunat, viritinreiät ja viitemerkinnät erotellaan vientirooleilla.

Vientialue lasketaan valitun sisällön tarkoista millimetrirajoista ja oletusarvoisesta 10 mm marginaalista. Kaikki seitsemän osatyyppiä saavat kätisyyden mukaisen suunnan ennen layoutia; vasenkätisen fyysinen peilaus, kaarien sweep, pisteet ja bounds käsitellään kerran, kun taas tekstit, kalibrointi ja mittatiedot luodaan normaalisti. Yksittäinen osa saa oman kokoisen alueen ilman koko kitaran tyhjää arkkia. SVG ja mukautettu PDF käyttävät tätä aluetta; A4/A3-PDF jakaa saman alueen 1:1-sivuille 10 mm limityksellä ilman tarpeettomia tyhjiä sivuja. DXF sisältää vain valitut entiteetit millimetreinä ja nimetyillä tasoilla. PDF:n tulostusreitti avaa generoidun PDF:n selaimen katselimeen; tulostuksessa on käytettävä 100 % / Todellinen koko -asetusta.

Vienti-ikkunan **Dimension table** -asetus lisää kehystetyn, valittuihin osiin rajautuvan mittalistan. Yksiköksi voi valita millimetrit, tuumat tai molemmat. Lista sisältää vain mallista johdettavat mitat, esimerkiksi rungon, kaulan, otelaudan, lavan ja kaulataskun mitat sekä erilliset kaulan ja otelaudan päätyvarat. Mittalaatikko lasketaan vientialueeseen mukaan, eikä se muuta kappaleen 1:1-mittakaavaa. Vientiasetukset ovat istuntokohtaisia eivätkä muuta projektia, undo-historiaa tai v11-tallennetta. Vientidialogi näyttää kätisyyden, ja valinnainen mittalaatikko sisältää Handedness-rivin. **Centerlines**-valinta näyttää tai piilottaa katkoviivaiset keskiviivat etu- ja takarungossa, kaulassa, otelaudassa ja kaulataskussa; lapa ei saa uutta keskiviivaa. PDF:n oletus on päällä ja SVG/DXF:n pois päältä. Valinta on erillinen **Nut/bridge references** -valinnasta; taskun suukäyriä ei viedä.

The **Neck pocket** export uses the same canonical `pocketTemplateGeometry(document).cut` as the editor. It is one closed `CUT_OUTER` perimeter containing the editor's upper-body material and an open neck-entry notch: the pocket mouth is not closed by a transverse cut or reference line. There is no separate `ROUTE_NECK_POCKET`; the optional exact centreline remains a clipped `REFERENCE_CENTERLINE`. The shared bottom is `max(pocket end Y) + 20 mm`, and the export fails closed with **No neck has been created.** or the shared invalid-template diagnostic when the template cannot be derived; there is no manual fallback. SVG, DXF and PDF use the same segments and retain 1:1 millimetre geometry. This local correction has not been published.

## Takapuolen elektroniikkapotero

Uudessa projektissa on yksi valmiiksi sijoitettu elektroniikkapotero. Se näkyy vain Taka-kuvassa ja sen pikkukuvassa. Lähtömuodon kaksi erillistä suljettua reunaa on muunnettu käyttäjän potero.svg-tiedostosta sovelluskoodiin; lähteen ulkomitta on noin 176,0669 × 81,3628 mm. Vanhojen projektien tallennetut mitat säilyvät, mutta niiden profiilimuoto korvautuu samalla uudella muodolla käyttäjän hyväksymän suoran korvauksen mukaisesti. Tätä paikallista muutosta ei ole vielä julkaistu.

Valitse potero napsauttamalla sen sisäpuolta tai reunaa. Vedä poteroa siirtääksesi sitä, tai venytä neljästä sivukahvasta. Vastakkainen reuna pysyy paikallaan. Molemmat reunat, niiden lovet ja niiden välinen tukireunus venyvät yhdessä. Työkalurivi näyttää näkyvän vaakamitan ja pystymitan millimetreinä tai tuumina. Valittu potero liikkuu nuolinäppäimillä 1 mm ja Shiftillä 10 mm; kohdistetun sivukahvan oman akselin nuoli muuttaa kyseistä reunaa.

Yksi valmis veto on yksi kumottava muutos. Escape ja keskeytynyt osoitinele peruuttavat vedon. Poteron oma kelpaamaton siirto tai venytys säilyttää viimeisen kelvollisen esikatselun. Rungon myöhempi muutos voi jättää poteron ulkopuolelle: se näkyy punaisena ja valittaessa korjausohjeella. Tällaisen projektin voi tallentaa ja avata korjattavaksi. Potero ei siirry tai pienene itsestään. Keskeneräinen kaulaluonnos estää poteron muokkauksen. Viestialueen korkeus pysyy vakiona, jotta ilmoituksen ilmestyminen tai poistuminen ei katkaise vetoa.

V11 tallentaa body.rearElectronicsCavity-rakenteeseen versionoidun profiiliviitteen, keskipisteen sekä näkyvät vaaka-/pystymitat. Puuttuva potero (null) säilyy puuttuvana. Tässä vaiheessa ei ole lisää-/poista-toimintoa, kiertoa, solmueditointia tai reunojen erillistä säätöä. Potero sisältyy Taka-rungon vientiin omilla ROUTE_REAR_RECESS- ja ROUTE_REAR_INNER-rooleillaan, mutta erillistä vain-poteron vientivalintaa ei ole. Poteron polut eivät muuta rungon tai kaulataskun CUT-geometriaa.

## Rajaus

Ohjelmaan ei kuulu Z-akselia, jyrsintäsyvyyksiä tai 3D-mallia tässä eikä myöhemmissä vaiheissa. Yleinen CAD/SVG-tuonti, hybridin muokkaustyökalut, muiden 2D-hardware-kolojen lisääminen on myöhempi vaihe. Mikrofonikolojen tarkistus rajoittuu 2D-geometriaan: rungon, kaulataskun, tallan kontaktikäyrän ja muiden kolojen leikkaus tarkistetaan, mutta se ei todista jyrsinterän, syvyyden, laitteiston, rakenteen tai fyysisen kappaleen sopivuutta. FretFactory-kaulatuonti tunnetusta `#state=`-URL:sta ja siihen perustuva automaattinen kaulatasku ovat toteutettu; FretFactoryn lähde pysyy erillisenä ja muuttumattomana. `CDR/` ja muunnetut suuret referenssit ovat paikallista taustamateriaalia eivätkä kuulu sovellusbundleen tai Git-seurantaan. Käynnistyksen bodytemplate on ennalta muunnettu lähdeaineisto, ei käyttäjän ajonaikainen CDR-tuonti. Toteutuksen rajaus ja varmennusnäyttö ovat [FEATURE_BRIEF.md](FEATURE_BRIEF.md)-tiedostossa.
