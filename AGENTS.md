# GTRfactory

Projektin juuri on repositorion juuri; päähaara on `main`. Manifestin engines-raja on Node `>=24.15.0 <25` ja npm `>=12.0.1 <13`; käytä Node 24.15.0:tä ja npm 12.0.1:tä (`.nvmrc`).

## Komennot

- `npm ci` asentaa lukitut riippuvuudet.
- `npm run dev` palvelee vain osoitteessa `http://127.0.0.1:5174`.
- `npm run preview` palvelee tuotantobuildin vain osoitteessa `http://127.0.0.1:4174`.
- `npm run build` tekee tuotantobuildin; sen jälkeen `npm run preview` palvelee buildin vain osoitteessa `http://127.0.0.1:4174`. `npm run typecheck`, `npm run test:run`, `npm run test:port-conflict`, `npm run build` ja `npm run test:e2e` ovat sovelluksen tarkistuskomennot. Ylläpidettävyyskierros 4:n dokumenttitransaktioiden kohdennettu ajo oli 7/7 PASS, yksikkö- ja integraatioajo 161/161 PASS (22 tiedostoa), 108/108 store- ja geometriapariteetti, 36/36 elepariteetti, tyyppitarkistus, muotoilutarkistus ja tuotantobuildi PASS. Sapluunageometrian kohdennettu ajo oli 22/22 PASS, laaja yksikkö-/integraatioajo 172/172 PASS (23 tiedostoa), riippumaton geometriakoe 27/27 PASS, front/back-regressio 104/104 PASS ja täysi paikallinen E2E-ajo 92/92 PASS (3,8 min, exit 0). Store delegoi dokumenttitransaktiot sisäiseen `documentTransactions`-moduuliin; sapluunageometria käyttää erillistä puhdasta `templateGeometry`-moduulia. Aiempien kierrosten erottelut säilyvät. Tarkat lähteet ovat FEATURE BRIEFin ledgerissä; aiempien kierrosten merkinnät säilyvät erillisinä.

Suorita asennus, buildit ja testit projektin juuressa peräkkäin, ei rinnakkain. Prettierin aktiivinen muotoilu tehdään komennoilla `npm run format` ja `npm run format:check`; niiden rajaus on `src/**/*.{ts,tsx,css}` vendorin ulkopuolelta, `tests/**/*.ts`, kolme Vite/Vitest/Playwright-konfiguraatiota ja `scripts/check-port-conflict.mjs`. JSON-, vendor-, referenssi-, tutkimus- ja dokumenttitiedostoja ei muotoilla. `test:port-conflict` tarkistaa sekä dev- että preview-portin Vite-konfiguraation mukaisesti. UI-muutoksissa käytä tuoretta buildiä ja tarkista selainkonsoli. E2E-testit käyttävät projektin omaa Playwright-riippuvuutta ja asennettua Microsoft Edgeä; kapea koe on iPhone 13 -kokoinen Chromium-simulaatio, ei fyysinen puhelin- tai Safari-koe. Testit eivät saa nojata Codexin sisäisiin runtime-polkuihin. Kiinteän portin varaus on virhepolku, ei syy siirtyä toiselle portille.

## Rajat ja dokumentointi

`FEATURE_BRIEF.md` omistaa tuote- ja vaihekohtaisen rajauksen sekä varmennusnäytön. `README.md` kuvaa vain toteutunutta nykytilaa. Yhteisen runko- ja kaulaeditorin toteutunut käyttö, v11-projektiformaatti (oikeakätinen v10 luetaan v11:ksi) ja neljän headstock-mallin valinta, yhdeksän nimettyä pickup-suunnitteluprofiilia, 22-nauhaisen oletuskaulan kohdistus 17. nauhasta ja erilliset päätyvarat kuvataan siellä. Vain v11-projektit tallennetaan. Oikeakätinen v10 luetaan muistiin v11:nä; v10:n vasenkätinen tai muu kätisyysarvo sekä puuttuva/virheellinen v11-arvo hylätään atomisesti. V1–v9 hylätään ennen nykyisen työn korvaamista eikä yleistä migraatiota luvata. Sapluunageometria muodostaa etu- ja takarungon sekä automaattisen suljetun taskukontuurin millimetreinä; etu/taka säilyttävät lähteen tarkat viiva- ja Bézier-kontrollit, taka peilaa kanonisen geometrian ja tasku käyttää De Casteljau -katkaisua sekä ympyräkaaria. Taskun oletusleikkaus on taskun pääty + 20 mm eikä kameran rajaus; keskiviiva ja alkuperäiset kaulaliittymän suukäyrät ovat erillisiä viitteitä. Virheellinen tai tukematon topologia palauttaa diagnostiikan ja säilyttää editorin muokattavana. Yleinen CAD/SVG-tuonti, hybridipiirto ja muiden 2D-hardware-kolojen jatkokehitys säilyvät FEATURE BRIEFissä. PDF-, DXF- ja SVG-vienti on toteutettu; sen varmennuksen rajat säilyvät FEATURE BRIEFissä. Z-akseli, jyrsintäsyvyydet ja 3D on rajattu pysyvästi pois. Älä kuvaa suunniteltuja 2D-koloja tai valmistusvientejä valmiina.

CDR-alkuperäiset, muunnetut suuret referenssit, riippuvuudet, buildit ja testiraportit pidetään Gitin ja sovellusbundlen ulkopuolella. Analyysin Markdown- ja JSON-tiedostot voivat olla seurattavia. Runkoeditorin kanoninen geometria ja projektitiedosto käyttävät millimetrejä. Uusi projekti aloittaa 25,5 tuuman / 22 nauhan kaulalla: 17. nauha kohdistetaan oletuksena kiinteään keskinodeen offsetilla 0, kaulan päätyvara on 10 mm ja otelaudan päätyvara 16,35 mm. Otelaudan päätyvaran on oltava aidosti suurempi, ja viimeisen nauhan koko PCHIP-käyrän on pysyttävä fyysisen pyöristetyn kantapään sisällä. Kaula ja lapa valitaan suoraan Etu-kuvasta ja näkymät pikkukuvasta; erillistä Kaula-sivua ei ole. Lavan valinta lähentää näkymää ja avaa vain sallitut vapaat node- ja kahvamuokkaukset. Kaulaluonnos on tilapäinen ja hyväksytään yhtenä undo-askeleena. Nykyinen kaulaton v11-template ei muuta tallennettua dokumenttia ennen hyväksyntää. Kaulaintegraatio käyttää GTRfactoryn omaa, FretFactory HEADiin `89f94c0e693b75528a41ac8fd8b682c04899f7fb` sidottua vendor-aluetta. Kitaralapa on tuettu 6/7/8-kielisille kauloille: kuusikieliselle ovat Inline, 3+3 — Lapa 2 ja 3+3 — Lapa 3, 7/8-kieliselle Inline. Inline-reunan neljä päätyasemaa ovat suojattuja; 3+3-malleissa solmut 0/1/2/6/7/8 ovat suojattuja ja 3/4/5 vapaita, ja 2.out/6.in ovat vapaat liittymäkahvat. V11 tallentaa pakollisen handedness-arvon sekä versionoidun kanonisen lapamuodon, kaulan parametrit, sijoituksen, molemmat päätyvarat, laskentatuloksen snapshotin, muuttumattoman liittymäreferenssin sekä mikrofonikolojen profiiliviitteet ja sijainnit. Uuden kaulan yhteydessä `body.neckPocket` on `null`; nykyisessä v11:ssä voi olla manuaalinen taskuluonnos ilman kaulaa, mutta tämä ei laajenna tiedostotukea v10:tä vanhempiin versioihin. Tallennettu offset säilyy; erillinen Kohdista-toiminto tai nauhan vaihtaminen nollaa sen. FretFactory säilyy erillisenä ja muuttumattomana. Taskun collision- ja containment-tarkistukset eivät todista valmistuskelpoisuutta.

GTRfactory-työ ei muuta muita työtiloja ilman erillistä käyttäjävaltuutusta. Automaattiset testit, paikallinen selain, ladattu valmistusartefakti ja fyysinen laite-/kenttäkoe ovat eri varmennustasoja; yhtä ei saa kuvata toisen näytöksi. PDF-, SVG- ja DXF-artefaktit on varmennettu paikallisesti. Natiivia käyttöjärjestelmän Save As -dialogikoetta, julkaistua ympäristöä tai fyysistä laite-/valmistuskoetta ei ole varmennettu. Selainkoe on paikallinen Edge ja mobiilinäyttö Chromium-simulaatio.

Noudata lisäksi käyttäjän globaalia työnkulkua ja sen agenttirooleja, delegointikynnyksiä sekä FEATURE BRIEF- ja VERIFICATION LEDGER -sopimuksia. Älä commitoi, pushaa, avaa PR:ää tai julkaise ilman erillistä käyttäjävaltuutusta.



Elektroniikkapotero käyttää v11:n body.rearElectronicsCavity-rakennetta; oikeakätinen v10 luetaan tähän muotoon: versionoitu potero-v1, keskipiste ja näkyvät vaaka-/pystymitat tai null. Uusi projekti aloittaa yhdellä poterolla kohdassa (0, 210) mm; horizontalMm/verticalMm ovat noin 176,0669 × 81,3628 mm, ja nykyinen Back-muunnos vaihtaa lähdeakselit, ja Left-handed lisää siihen saman effectiveMirror-muunnoksen ilman kaksinkertaista peilausta. Taka-kuvan kaksi tarkkaa kontuuria muuttuvat yhdessä; neljä sivukahvaa säilyttää vastareunan. src/electronicsCavity omistaa profiilin/muunnoksen ja src/geometry/containment.ts poteron adaptiivisen sijoitustarkistuksen. Pickupin aiempaa containmentia ei refaktoroitu. Poteron oma virheellinen muutos hylätään, mutta bodymuutoksen ulkopuolelle jättämä potero voidaan tallentaa/avata korjattavaksi. Valinta näyttää diagnostiikan. Ei Z-akselia, kiertoa, vapaita nodeja tai useita poteroita. Potero viedään Taka-rungon mukana kahdella erillisellä ROUTE-roolilla; erillistä vain-poteron vientivalintaa ei ole. Tilaviestit eivät saa muuttaa canvasin kokoa kesken vedon.




## Kätisyys — varmennettu 14.9.2026

Lopullinen näyttö: 246/246 yksikkö-/integraatiotestiä, tyyppitarkistus/muotoilu/build PASS; kätisyys-E2E 4/4 desktop/mobiili, riippumaton geometriakoe 4/4 ja 18/18 SVG/DXF/PDF-artefaktia PASS. Toolbarin yksi **Right-handed / Left-handed** -toggle vaihtaa koko instrumentin kätisyyden. Uusi projekti on oikeakätinen. Kanoninen millimetriageometria säilyy oikeakätisenä; oikeakätisen kaula osoittaa oikealle ja vasenkätisen vasemmalle kaikissa kolmessa editorinäkymässä. Vasen käyttää effectiveMirror-muunnosta `back XOR left` ja siihen liittyvää esityssuunnan kiertoa, joten body, kaula/lapa, bass4, pickupit ja takapotero peilautuvat yhdessä. Yhteinen näyttö→maailma-delta-muunnos ohjaa myös poteron kahvoja ja nuoliliikkeitä; tekstit ja asteikot säilyvät oikeinpäin, eikä bass/treble-semantiikka vaihdu.

Kätisyyden vaihto on yksi undo/redo-askel ja säilyy avauksessa, tallennuksessa ja mallinvaihdoissa. New aloittaa oikeakätisen projektin. Aktiivinen veto tai avoin neck draft estää vaihdon, kunnes luonnos hyväksytään tai perutaan. Projektiv11 vaatii `handedness: right|left`; oikeakätinen v10 luetaan muistiin v11:nä. V10:n puuttuva handedness tarkoittaa right-arvoa, mutta v10:n left/muu arvo hylätään. V11:n puuttuva tai virheellinen arvo sekä v9 ja sitä vanhemmat versiot hylätään atomisesti. Passiivisen legacy-`bass-5-inline`-avaimen puhdistus sallitaan vain v10-lukupolussa; v11:ssä ja aktiivisena bass5 hylätään.

PDF-, SVG- ja DXF-viennin kaikki seitsemän osatyyppiä saavat kätisyyden mukaisen suunnan ennen layoutia: pisteet, Bézier-kontrollit, ympyräkeskukset ja kaarikeskukset muunnetaan, kaaren sweep vaihdetaan tarvittaessa ja bounds lasketaan uudelleen. Tekstit, kalibrointi, sivutus ja mittataulukko luodaan normaalisti. Vientidialogi näyttää kätisyyden ja valinnainen mittalaatikko sisältää Handedness-rivin. Tämä ei muuta FretFactory/vendor-aluetta, portteja tai riippuvuuksia.
